## 한 문장 정의

일반 PRD 와 AI PRD 의 결정적 차이는 **결과가 deterministic 하지 않다**는 점이다.

```text
일반 기능   버튼 클릭 → 항상 A
AI 기능     Input → Model → 확률적인 Output
```

그래서 "무엇을 만든다"만으로는 부족하고, **어떻게 판정하고 실패하면 어떻게 하는지**를 같이 적어야 한다.

## 반드시 들어갈 항목

| 항목 | 정의할 것 |
|---|---|
| Problem | 무슨 문제인가 |
| User | 누가 쓰는가 |
| Input | AI 에게 무엇을 주는가 |
| Process | AI 가 무슨 작업을 하는가 |
| Output | 어떤 형태로 돌려주는가 |
| **Evaluation** | 잘했는지 어떻게 판단하는가 |
| **Exception** | 실패하면 어떻게 하는가 |
| **Human Review** | 사람 확인이 필요한가 |
| **Logging** | 어떤 데이터를 남기는가 |

## IPO 에 두 가지를 더한다

기존에 쓰던 `Input · Process · Output` 에 **`Evaluation` 과 `Fallback`** 을 추가하면
AI 기능 정의가 눈에 띄게 좋아진다.

## 실패 지점

- 정확도 목표만 적고 **측정 방법**을 안 적는다
- 실패 시 동작이 없어 장애 때 아무 화면도 안 나온다
- 로깅 항목이 없어 나중에 개선 근거를 못 만든다

## 글에서 답할 질문

- AI PRD 는 뭐가 다른가요
- 요구사항을 어떻게 검증 가능하게 쓰나요
- 실패 시 동작은 어떻게 정의하나요
- 무엇을 로깅하나요
