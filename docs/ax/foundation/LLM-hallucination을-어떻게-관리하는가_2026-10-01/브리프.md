## 각도

## 연결할 기존 글
/labs/nlp-core-visual-study-guide/

## 한 문장 정의

Hallucination 은 모델이 **근거가 없거나 틀린 내용을 사실처럼 생성하는 현상**이다.
기업 환경에서는 "완전히 없애겠다"가 아니라 **발생 확률과 피해를 어떻게 통제할 것인가**가 현실적인 목표다.

## 방어는 여러 층으로

| 층 | 하는 일 |
|---|---|
| 입력 통제 | 질문 범위를 제한한다 |
| Retrieval | 근거 문서를 제공한다 |
| Prompt | 근거가 없으면 답하지 않게 한다 |
| Citation | 어떤 정보를 썼는지 보여준다 |
| Validation | 특정 값·형식은 Rule 로 검증한다 |
| Fallback | 신뢰하기 어려우면 답하지 않는다 |
| Human Escalation | 중요한 판단은 사람에게 넘긴다 |

## 모든 문제를 RAG 로 풀지 않는다

가격이나 계약조건을 LLM 기억으로 답하면 위험하다.

```text
가격 질문 → DB/API 조회 → 정확한 값 확보 → LLM 은 설명만 수행
```

**값은 시스템이 가져오고, LLM 은 문장만 만든다.**

## 실패 지점

- 근거를 붙였지만 사용자가 원문을 열어볼 수 없다 → 확인이 불가능하니 안 쓴다
- "모르겠다"를 허용하지 않아 아무 말이나 하는 시스템이 된다
- 평가셋에 답하지 않아야 하는 질문이 없어 기권 능력이 측정되지 않는다

## 근거로 쓸 경험

**가전 브랜드 인증점 챗봇** — fallback 과 상담원 전환 설계.

> 실제 서비스에서는 AI 가 모든 질문에 답하는 것보다 **언제 답하지 않아야 하는지**를 정의하는 것이 중요했다.

## 글에서 답할 질문

- 환각을 어떻게 막나요
- Prompt 로 충분한가요
- 가격 같은 건 어떻게 처리하나요
- 답하지 않는 기준은 무엇인가요
- 환각률은 어떻게 측정하나요
