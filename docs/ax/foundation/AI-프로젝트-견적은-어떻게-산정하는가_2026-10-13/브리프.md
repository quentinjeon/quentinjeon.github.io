## 한 문장 정의

AI 프로젝트 견적을 **개발 기간만으로 잡으면 거의 틀린다.** 비용은 모델 호출이 아니라 주변에서 난다.

## 비용이 실제로 나오는 곳

| 항목 | 왜 커지나 |
|---|---|
| **데이터 준비** | 엑셀 20개에 흩어져 있고 형식이 다르면 정리부터 해야 한다 |
| **시스템 연동** | ERP·CRM·TMS 연결은 예상보다 공수가 크다 |
| **AI 평가** | 모델 호출이 아니라 평가셋과 검증 프로세스를 만드는 일 |
| **보안** | SSO·RBAC·감사로그 요구가 뒤늦게 들어온다 |
| **운영** | Prompt·Knowledge Base 를 누가 관리할지 정해야 한다 |

## 견적 구조

항목을 이렇게 나누면 설명이 명확해진다.

```text
Discovery · Data · AI · Application
Integration · Infrastructure · QA · Operation
```

**운영(Operation)을 빼놓고 견적을 내면 본사업에서 반드시 문제가 된다.**

## 실패 지점

- 모델 API 비용만 계산하고 사용량 증가를 반영하지 않는다
- 데이터 정리 공수를 "고객이 주겠지"로 가정한다
- 평가 없이 넘겼다가 검수 단계에서 분쟁이 난다

## 글로 쓸 때 주의

경쟁 글은 전부 "월 100달러~25만 달러" 같은 넓은 범위만 제시한다.
**항목 구조**를 보여주는 게 차별점이다. 고객사 금액은 쓰지 않는다.
