## 각도

## 한 문장 정의

단계마다 **묻는 질문 자체가 다르다.**

| 단계 | 질문 |
|---|---|
| **PoC** | 기술적으로 가능한가 |
| **Pilot** | 제한된 실제 환경에서도 작동하는가 |
| **Production** | 회사 시스템으로 지속 운영할 수 있는가 |

## 무엇이 늘어나는가

PoC 에서는 Excel 을 Python 으로 분석해도 된다. 본사업에서는 이것들이 전부 필요하다.

```text
API · DB · 보안 · 로그인 · 권한 · 개인정보 · 로그
관리자 화면 · 장애처리 · SLA · 비용 · 모니터링
```

## 실패 지점

PoC 에서 통과했는데 본사업에서 엎어지는 전형적인 이유:

- 운영 주체가 정해지지 않음 (누가 Prompt·Knowledge Base 를 관리하는가)
- 기존 시스템 연동 공수를 과소평가
- 평가셋이 없어 "좋아졌다"를 증명하지 못함
- 정확도는 올랐는데 **사용자 행동이 바뀌지 않음**

## 내 사례 (익명)

**건설사 B** — 약 5만 건 규모의 하자접수 데이터에서 고객이 요구한 중복·재접수·재발 구분 가능성을 검토하는 단계.

본사업으로 가면 이렇게 확장된다.

```text
신규 접수 → AI 분석 → 유사 접수 제시 → 담당자 확인
→ 상태 변경 → 결과 저장 → 학습/평가 데이터 활용
```

여러 현장을 연결하면 현장별 발생률·입주 경과기간 비교·반복 유형·공종별 문제·처리 리드타임 같은 **운영 체계**까지 간다.
