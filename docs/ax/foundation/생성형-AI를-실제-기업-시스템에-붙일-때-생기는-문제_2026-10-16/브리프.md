## 실제로 생기는 문제

| 영역 | 문제 |
|---|---|
| **데이터** | 사내 문서 자체가 틀렸거나 중복이다. AI 가 틀린 게 아니라 원본이 틀렸다 |
| **권한** | 사용자마다 볼 수 있는 데이터가 다르다 |
| **연동** | AI 혼자 업무를 끝낼 수 없다. ERP·CRM·그룹웨어를 읽고 써야 한다 |
| **안정성** | LLM API 오류·timeout 이 난다 |
| **지연** | 답변이 20초 걸리면 직원이 안 쓴다 |
| **비용** | 사용량이 늘면 토큰 비용이 커진다 |
| **평가** | 모델·프롬프트를 바꾸면 재검증해야 한다 |
| **규정** | 개인정보·내부기밀 처리 문제 |
| **변화 관리** | **기능이 좋아도 직원이 안 쓰면 실패다** |

## 가장 과소평가되는 것

변화 관리다. AX 프로젝트는 결국 세 가지를 같이 봐야 한다.

```text
Technology + Process + People
```

기술만 보면 "좋은 시스템인데 아무도 안 쓰는" 결과가 나온다.

## 실패 지점

- 파일럿 사용자만 쓰고 확산이 멈춘다
- 기존 업무 절차를 안 바꾸고 도구만 얹는다
- 담당자가 바뀌면 시스템이 사라진다
